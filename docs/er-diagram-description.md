# Описание ER-диаграммы базы данных

Диаграмма отображает структуру реляционной базы данных для сервиса каталога образовательных учреждений.

## Основные сущности

1.  **users (Пользователи)**: Хранит учетные данные (email, хеш пароля) и роль (`user` или `admin`).
2.  **profiles (Профили)**: Расширенная информация о пользователе (ФИО, возраст). Связана с `users` отношением 1:1. Содержит ссылку на город проживания (`city_id`).
3.  **cities (Города)**: Справочник городов. Используется для географической привязки пользователей и учреждений.
4.  **institutions (Учреждения)**: Каталог учебных заведений. Привязаны к городу (`city_id`).
5.  **reviews (Отзывы)**: Оценки и комментарии пользователей к учреждениям. Связывает `users` и `institutions` (Many-to-One с обеих сторон).
6.  **favorites (Избранное)**: Таблица-связка для реализации отношения Many-to-Many между пользователями и учреждениями. Позволяет пользователю сохранять список понравившихся мест.
7.  **preferences (Предпочтения)**: Настройки пользователя для начальной фильтрации (желаемый город поступления, направление). Связана с `users` 1:1.

## Ключевые связи

*   **Пользователь — Профиль**: Один пользователь имеет один профиль.
*   **Город — Учреждения**: В одном городе может находиться много учреждений.
*   **Пользователь — Отзывы**: Один пользователь может написать много отзывов.
*   **Пользователь — Избранное**: Многие пользователи могут иметь много избранных учреждений (реализовано через таблицу `favorites`).
*   **Пользователь — Предпочтения**: Один пользователь имеет один набор предпочтений, которые могут ссылаться на конкретный город из справочника `cities`.
